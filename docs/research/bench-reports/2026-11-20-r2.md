# Bench report #2: local-model harness measurement (2026-11-20)

First measurement pass of the harness-gain suite (`benchmarks/harness-gain/`,
merged in #291/#294). Model pinned to `Qwen--Qwen3-8B` on the local fusion-mlx
engine (`127.0.0.1:11434`), matching the small-model harness-adaptation
hypothesis from report #1.

## 1. Environment

- fusion-code binary built from `origin/main` (v0.8.11) in isolated worktree
- Engine: fusion-mlx local, model `Qwen--Qwen3-8B` (40960 ctx), engine key via `FUSION_CLIENT_KEY`
- Runner fix shipped as #297: command verifiers crashed under Bun's
  `spawnSync` signature (merged-code defect found by post-merge acceptance)
- Harness drivers: fusion-code `-p --max-turns 12`; opencode `run`; goose `run --text` (v1.60.2)

## 3. Observations

- Tool-call-as-text failure mode confirmed live: Qwen3-8B emits
  `call_<id>{json}` as plain stdout instead of a tool_use block
  (captured in T02 log of run 2026-11-20T10-08-36-507Z). Session ends after
  one such turn. This is the small-model harness-adaptation target, not a
  harness bug.
- Engine contention hazard: two distinct failure sources during measurement.
  (1) memory_guard ceiling (~116/119.5 GB, big-prompt requests aborted).
  (2) External SIGTERM restarts of the engine (21:54, 21:58, 22:01 local,
  sender unattributed ppid=1 in `_parent_watchdog` logs) — during teardown
  the listener refuses connections instantly and every task starting in
  that window dies with "Local inference service unavailable".
  fusion-code's 3s health probe behaved correctly (engine genuinely down).
  Runs with >half the tasks poisoned were discarded; quiet-window protocol
  (3 consecutive 512-token probes) required before a valid run.
- fusion-code runner defaults to a coder model (`Qwen2.5-Coder-32B`) when
  `FUSION_MODEL` is unset — sensible default, but benchmarks must pin.
- Permission-bypass fix (part of the recovery-loop PR, branch
  `fix/tool-call-text-recovery`): `-p` runs die on the first Edit
  permission prompt ("Aborted after 5 consecutive identical tool errors").
  Runner now passes `--dangerously-skip-permissions` — valid because the
  suite runs in throwaway temp git repos with no network. Suite runs from
  before this fix underestimate task walls (fast permission deaths) and
  are kept only as provisional baselines.
- Recovery loop shipped and E2E-verified on the same branch (see the
  small-model tool-calling survey §6): Read-shaped text recovers to a
  real tool_use after one correction; Edit-shaped text does not — the 8B
  model re-emits identical `Edit({...})` text through all 2 corrections.
  Second correction now suggests whole-file `Write` (edit-format
  escalation, aider finding: weak models do better whole than diff).
- Verifier design trap (fixed in #297): a CRLF fixture ending in `exit 0\r`
  still exits 0 under `bash build.sh` (shebang ignored, `set -e\r` errors
  without enabling errexit, `exit 0\r` accepted) — the untouched broken
  fixture passed and a dead agent run scored resolved=true. Deterministic
  verifiers must be proven to fail on the untouched fixture, not just pass
  on a correct one.

## 4. Conclusions / next work

- **Harness fixes were worth 0 → 3 tasks** (0/20 provisional pre-fix run
  vs 3/20 valid run, same model, same engine): the permission bypass and
  the tool-call-as-text recovery loop are the difference. Harness defects
  masked all model capability in the first pass — measure the harness
  before blaming the model.
- **Qwen3-8B ceiling is the easy/medium boundary**: every easy task
  resolves, zero medium/hard tasks do. Resolve-rate gains for local small
  models now come from (a) model capability (trainer flywheel, better
  local models) and (b) ACI simplification, not from fixing harness
  defects — those are done.
- textEmissions=0 in a full valid run is the first clean engine+harness
  datapoint; keep the metric in every future run so regressions (engine
  upgrade, prompt growth) surface as a nonzero count instead of silent
  resolve-rate loss.
- Cross-harness numbers (opencode, goose) will say whether the 3/20 is a
  model ceiling or a fusion-code-specific ACI ceiling. opencode partial
  results already show a second harness-design lever: fusion-code's
  `--max-turns 12` bounds hopeless tasks (mean wall ~130s, no timeouts)
  while unbounded opencode burns the full 600s on 10/13 tasks — same
  model, same engine, 5x+ wall saving on lost causes with no
  resolve-rate gain for the unbounded side.
- Verifier-hang trap (second verifier-design lesson, found by the
  opencode run): T13's fixture contains an unfixed infinite-retry loop;
  pytest on the untouched file hangs forever. A verifier must fail, not
  hang, on an untouched fixture — the CRLF trap (#297) was the fail-fast
  variant, this is the fail-terminating variant. Runner now bounds
  pytest/command verifiers at 60s (recovery-loop PR branch).
- Verifier-passes-on-untouched trap (third lesson, found by the goose
  run): T08 (dedup refactor) was verified by behavior tests that pass on
  the untouched file — every harness scores "resolved" for doing
  nothing. New count-max verifier bounds duplicate-marker occurrences
  (untouched fails at 3, deduped passes at 1). opencode's T08 resolve
  was retracted. Design rule now explicit: every verifier must be
  demonstrated to (a) fail on the untouched fixture, (b) terminate, and
  (c) pass on a hand-made correct solution.
