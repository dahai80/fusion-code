## 3. First two measured work items

**Item 1 — Local-model harness gain (home-field metric, highest priority).**
Fixed task suite (~20 coding tasks, mixed difficulty), same MLX checkpoint (e.g. Qwen3 8B 4bit via fusion-mlx), three harnesses: fusion-code vs opencode vs Aider. Metric: task resolved rate + tokens/task + tool calls/task. Deliverable: reproducible eval script + first numbers table in report #2. Success criteria: suite runs end-to-end unattended; every number has the exact model build + harness version recorded.

**Item 2 — Token/tool efficiency baseline from session jsonl.**
Reuse the trajectory collector (`fusion-code trajectory collect`) to derive per-task token and tool-call distributions from real sessions on v0.8.5. This is the before-numbers for any harness optimization (prompt slimming, tier dispatch). Success criteria: script + one committed baseline JSON in `benchmarks/` (branch only); numbers reproducible by rerunning the script.

Both are research artifacts — no mainline code change; eval scripts land on this branch and go up as a PR.
